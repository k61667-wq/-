# 뉴스포스트 운영 자동화 — 구축 & 운영 가이드

설계 배경과 근거는 `docs/뉴스포스트_운영자동화_설계서.md`를 먼저 보세요.
이 문서는 **실제로 만드는 순서**입니다.

## 0. 전체 그림

```
[온보딩 1회]
업체 등록 → company_id 자동발번 → 초대 → 계정 배정 → 키워드·필수기재 확정
                                              │
                                    메뉴 ① 콘셉트 풀 생성 (20개)
                                              │
                                              ▼
[건당 반복]
05 시트에 행 추가 → 업체명 선택 ──자동──▶ 정보 13개 열 자동 채움
                        │
              콘셉트 선택(미사용만 표시)
                        │
              메뉴 ② 초안 생성  ──▶ 제목 3안 · 본문 · 사진가이드
                        │
              1차 기계검수 자동 실행 (금지어·필수기재·반복)
                        │
              메뉴 ③ AI 2차 검수 (선택)
                        │
              ★ 사람 검수 — 사실 확인 ★
                        │
              최종_게시본문 자동 결합(상단+본문+하단)
                        │
              ★ 복사 → 당근에 붙여넣기 ★
                        │
              발행URL 붙여넣기 ──자동──▶ 상태·발행일·콘셉트사용·계정사용일·진행률
                        │
                        ▼
[전자동]  매일 알림 · 대시보드 · 중간보고 초안
```

## 2. Phase 1 — 시트 만들기 (1주차, 이것만으로 절감 40%)

### 2-1. 탭 7개 생성

`templates/뉴스포스트_시트구조.md`의 열 정의서 그대로 만듭니다.

```
01_Company_Master  02_계정관리  03_초대현황  04_콘셉트DB
05_뉴스포스트_작성  06_대시보드  07_보고로그
```

`data/뉴스포스트_*_seed.csv`를 각 탭에 가져오기 하면 헤더와 예시 행이 한 번에 들어갑니다.
(시드 CSV에는 **사람이 입력하는 열만** 들어 있습니다. 자동 열은 아래에서 수식으로 채웁니다.)

### 2-2. 자동 열에 수식 넣기

`05_뉴스포스트_작성` 2행에 아래를 넣고 아래로 복사합니다. (`$C2` = company_id)

| 열 | 수식 |
|---|---|
| D 업종 | `=IFERROR(XLOOKUP($C2,'01_Company_Master'!$A:$A,'01_Company_Master'!$C:$C),"")` |
| E 지역 | `=IFERROR(XLOOKUP($C2,'01_Company_Master'!$A:$A,'01_Company_Master'!$D:$D)&" "&XLOOKUP($C2,'01_Company_Master'!$A:$A,'01_Company_Master'!$E:$E),"")` |
| F URL | `=IFERROR(XLOOKUP($C2,'01_Company_Master'!$A:$A,'01_Company_Master'!$F:$F),"")` |
| H 메인키워드 | `…$L:$L` |
| I 롱테일 | `…$M:$M` |
| J 금지키워드 | `…$N:$N` |
| K 톤 | `…$O:$O` |
| L 필수기재 상단 | `…$S:$S` |
| M 필수기재 하단 | `…$T:$T` |

> 스크립트(`fillCompanyInfo_`)가 값으로도 채워줍니다. **수식과 스크립트 중 하나만 쓰세요.**
> - 수식 방식: Master를 고치면 미발행 행에 즉시 반영됨 (권장)
> - 스크립트 방식: 발행 시점의 값이 그대로 박제됨 (이력 보존에 유리)
> 실무에서는 **미발행 행은 수식, 등록완료 행은 값 고정**이 이상적입니다. 처음에는 수식으로 시작하세요.

`04_콘셉트DB` J열 (사용여부) — **이 수식이 이 설계의 핵심입니다.**

```
=IF(COUNTIF('05_뉴스포스트_작성'!$O:$O, $A2)>0, "사용됨", "미사용")
```

`03_초대현황` K·L·M열:

```
K (경과일)   =IF($F2="","",TODAY()-$F2)
L (알림필요) =IF(AND($G2="수락대기",$K2>=3),"Y","")
M (위험도)   =IF(AND($G2="수락대기",$K2>7),"🔴 재초대 필요","")
```

`02_계정관리` J열 (중복배정경고):

```
=IF($D2="","",IF(COUNTIF($D$2:$D,$D2)>1,"⚠ 중복",""))
```

### 2-3. 드롭다운 설정

| 대상 | 설정 |
|---|---|
| `05!B` 업체명 | 데이터 확인 → 범위 `01!B2:B` |
| `05!O` concept_id | `=FILTER('04_콘셉트DB'!A2:A, '04_콘셉트DB'!B2:B=$C2, '04_콘셉트DB'!J2:J="미사용")` 를 보조 시트에 만들고 그 범위를 참조 |
| `05!AC` 상태 | 기획, 초안, 검수대기, 수정요청, 승인, 등록완료 |
| `04!C` 카테고리 | 상품·서비스 소개, 노하우 공유, 매장 일상 |

### 2-4. 시트 보호 (건너뛰지 마세요)

자동 열(🔒 표시된 전부)을 선택 → 우클릭 → 범위 보호 → **"이 범위를 수정할 때 경고 표시"** 이상으로 설정.

보호를 안 걸면 누군가 필수기재 하단 셀을 덮어쓰고, 그 상태로 발행되고, 아무도 모릅니다.

### 2-5. 조건부 서식

| 대상 | 조건 | 색 |
|---|---|---|
| `05!W` | 텍스트 시작 `⛔` | 빨강 |
| `06!G` 페이스 | `<-0.1` | 빨강 |
| `06!I` 공백일수 | `>7` | 빨강 |
| `06!J` 잔여콘셉트 | `<5` | 노랑 |

## 3. Phase 2 — 스크립트 설치 (2주차, 절감 65%)

1. 스프레드시트 → **확장 프로그램 → Apps Script**
2. 기존 코드를 모두 지우고 `scripts/뉴스포스트_자동화.gs` 전체를 붙여넣습니다.
3. **저장** → **실행**을 눌러 최초 1회 권한 승인을 완료합니다.
4. **프로젝트 설정(⚙) → 스크립트 속성**에 추가:
   - `ANTHROPIC_API_KEY` = `sk-ant-...`
   - ⚠️ 코드나 시트 셀에 API 키를 쓰지 마세요. 시트를 공유하는 순간 키가 같이 나갑니다.
5. **트리거(⏰) → 트리거 추가** 2개:

| 함수 | 유형 | 설정 |
|---|---|---|
| `onEdit` | 스프레드시트에서 · 수정 시 | **설치형으로 등록** (단순 트리거는 메일 발송·외부 API 호출 권한이 없습니다) |
| `sendDailyAlerts` | 시간 기반 · 일 단위 | 오전 9~10시 |

6. 스프레드시트를 새로고침하면 상단에 **🥕 뉴스포스트** 메뉴가 생깁니다.

### 동작 확인 순서

1. `01_Company_Master`에 업체명 입력 → A열에 `CM-001`이 자동으로 뜨는지
2. 해당 행 선택 → 메뉴 **① 콘셉트 풀 생성** → `04_콘셉트DB`에 20행이 들어오는지
3. `05` 시트에 업체명 선택 → D~M열이 자동으로 채워지는지
4. 콘셉트 선택 → 메뉴 **② 초안 생성** → 제목 3안·본문이 들어오는지
5. W열에 `✅ 통과` 또는 `⛔ 차단: …`이 뜨는지
6. 일부러 본문에 "업계 최초"를 넣고 상태를 `승인`으로 바꿔보기 → **자동으로 `수정요청`으로 되돌아가야 정상**

6번이 되돌아가지 않으면 `onEdit`이 설치형 트리거로 등록되지 않은 것입니다.

## 4. Phase 3 — 대시보드·보고 (3~4주차, 절감 75%)

### 4-1. 대시보드 수식

`06_대시보드` A열에 업체명을 `01!B2:B`로 참조하고, 나머지를 수식으로 채웁니다.

```
D 완료      =COUNTIFS('05_뉴스포스트_작성'!$C:$C,$A2_id,'05_뉴스포스트_작성'!$AC:$AC,"등록완료")
E 진행률    =IFERROR(D2/C2,0)
F 기대진행률 =IFERROR((TODAY()-계약시작)/(계약종료-계약시작),0)
G 페이스    =E2-F2                        ← -0.1 미만이면 지연
H 최근발행일 =MAXIFS('05'!$AE:$AE,'05'!$C:$C,$A2_id)
I 공백일수  =IF(H2="",999,TODAY()-H2)      ← 7 초과면 노출 후보군 이탈
J 잔여콘셉트 =COUNTIFS('04'!$B:$B,$A2_id,'04'!$J:$J,"미사용")
```

> **I열(공백일수)이 이 대시보드에서 가장 중요한 숫자입니다.**
> 당근 소식은 최근 1주일 내 글만 노출 후보군에 듭니다. 진행률 100%여도 발행이 몰려 있으면 노출은 안 됩니다.

### 4-2. 중간보고

`01_Company_Master`에서 업체 행 선택 → 메뉴 **중간보고 초안 생성** → 기간 입력
→ Google Docs 초안 생성 + `07_보고로그` 자동 기록.

담당자는 **"6. 성과 해석 및 제안"만** 작성하고 발송합니다.

## 5. 운영 SOP

### 매일 (5분)

1. 아침 알림 메일 확인 — 초대 지연 / 발행 공백 7일+ / 정체 3일+ / 잔여 콘셉트 부족
2. 🔴 항목만 처리

### 건당 (18분)

1. `05` 시트 새 행 → 업체명 선택 (정보 자동 호출)
2. 콘셉트 선택 (미사용만 보임)
3. 메뉴 **② 초안 생성**
4. 제목 3안 중 택1 → S열
5. 본문 확인·수정 → U열
6. W열 기계검수 확인 — ⛔면 수정
7. (필요 시) 메뉴 **③ AI 2차 검수**
8. **★ 사실 확인 ★** — 가격·경력·자격·효능이 실제와 맞는가
9. 상태 → `승인` (차단이 있으면 자동으로 되돌아감)
10. Y열 `최종_게시본문` 복사 → 당근에 붙여넣기 + 사진 첨부
11. 발행 후 URL을 AD열에 붙여넣기 → **끝** (나머지 전부 자동)

### 업체 온보딩 (40분)

1. `01_Company_Master`에 업체명 입력 → company_id 자동 발번
2. 업종·지역·서비스·차별점 입력
3. 비즈프로필 진단 → 메인 키워드 5 / 롱테일 5 확정 → L·M열
4. **통신판매업 신고 대상 여부 판정** → P열 Y/N (Y면 Q·R열 필수)
5. 필수기재 상단·하단 확정 → S·T열
6. `02_계정관리`에 계정 배정 (중복 경고 확인)
7. `03_초대현황`에 초대 발송 기록
8. 메뉴 **① 콘셉트 풀 생성** → 20개

### 월 1회

- 중간보고 생성·발송
- 반응 좋았던 세부유형 확인 → 콘셉트 우선순위 조정
- 잔여 콘셉트 5개 미만 업체 보충 생성
- 유휴 계정(30일 미사용) 회수 검토
- API 사용량 확인

## 6. 비용

| 항목 | 월 |
|---|---|
| Google Workspace / Apps Script | 기존 (추가 0원) |
| Claude API (160건, 초안+검수) | 약 2~3만원 |
| 비밀번호 매니저 | 1~3만원 |
| **합계** | **약 4~6만원** |

`claude-opus-5` 기준 입력 $5 / 출력 $25 per 1M tokens.
건당 입력 ≈ 4K, 출력 ≈ 3K 가정 시 건당 약 130원. 160건이면 약 2만원 수준입니다.
비용을 더 낮추려면 초안 생성의 `effort`를 `low`로 내리거나 검수 모델만 낮추는 것을 먼저 검토하세요.

## 7. 자주 나는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 업체 선택해도 정보가 안 채워짐 | `onEdit`이 설치형 트리거로 없음 | 트리거 재등록 |
| `⛔ 차단`인데 승인이 됨 | 위와 동일 | 트리거 재등록 |
| 메뉴가 안 보임 | 권한 승인 미완료 | Apps Script에서 함수 1회 실행 |
| API 오류 401 | 스크립트 속성에 키 없음/오타 | `ANTHROPIC_API_KEY` 재등록 |
| API 오류 400 (thinking) | `budget_tokens`를 쓰면 현재 모델에서 거부됨 | `thinking: {type:"adaptive"}` 유지 |
| JSON 파싱 실패 | 모델이 설명을 덧붙임 | 프롬프트 "JSON만 출력" 문구 유지, `parseJson_`가 코드펜스는 처리함 |
| 콘셉트 드롭다운이 비어 있음 | 콘셉트 풀 미생성 또는 전부 사용됨 | 메뉴 ① 재실행 |
| 진행률이 안 맞음 | 상태가 `등록완료`가 아님 | 발행URL을 입력하면 자동 전환됨 |

## 8. 하지 말아야 할 것

- ❌ 당근 계정 **자동 로그인·봇 게시** — 약관 위반·계정 정지 위험. 등록은 사람이 붙여넣습니다.
- ❌ 시트에 **비밀번호·복구코드·2FA 시드** 저장 — 볼트 항목명만 적습니다.
- ❌ 자동 열 **덮어쓰기** — Master와 작성시트가 갈라지고, 틀린 필수기재가 발행됩니다.
- ❌ `04_콘셉트DB`의 **사용여부 수기 입력** — 반드시 수식으로만.
- ❌ **사람 검수 생략** — 사실 확인은 기계가 못 합니다. 법적 책임의 마지막 방어선입니다.
- ❌ 초안 **자동 재시도 루프** — API 비용이 조용히 늘어납니다. 재생성은 버튼으로만.
